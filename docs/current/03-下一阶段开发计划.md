# Aquafish 下一阶段开发计划

## 目标

把现有主题和 PF4J 运行底座升级为第三方开发者可依赖、可兼容、可诊断的扩展平台。

## 开发顺序

1. 拆分插件公开 API 与内部运行时，冻结第一版兼容边界。
2. 定义 Action、Filter、Event、Cell 和 Template Slot。
3. 定义插件权限、能力、依赖、迁移和前端入口清单。
4. 接入插件安装、升级、卸载、回滚、签名和审计。
5. 建立 Admin 菜单、路由、页面与设置 Schema 扩展协议。
6. 设计 Aquafish 模板数据模型、函数、标签和安全表达式。
7. 建立模板编译缓存、主题热更新失效和渲染性能基线。
8. 提供官方主题与插件脚手架、开发文档和兼容性测试套件。

## 阶段约束

- 在插件 API 冻结前，不继续增加大量仅有模块壳的业务模块。
- 插件 ClassLoader 只作为依赖隔离，不宣传为不可信代码沙箱。
- 主题和插件能力必须先有测试、版本和失败隔离，再开放给第三方。

## 验收条件

- 示例插件只依赖公开 SDK 即可编译和运行。
- 示例主题只使用公开模板模型即可完成内容、论坛和用户页面。
- 插件停用后不存在残留路由、菜单、Hook、线程或 ClassLoader 引用。
- 模板和插件升级具备兼容检查、回滚和可读诊断信息。
